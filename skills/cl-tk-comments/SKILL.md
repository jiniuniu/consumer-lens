# 评论区聚类

输入一个视频 id，输出**这条视频的评论区到底在讨论什么**，按语义聚成簇，再说每簇有什么用。
结果用 `cl_save` 存到本机，面板几秒后自动出现。

⚠️ **不要预设评论区在聊痛点。** 评论区可能在羡慕、玩梗、质疑真假、认亲、纯跑题 ——
这些都是真实信号，只是指向不同用途。带着"找痛点"的框去读，会把一个 40% 的人在喊
`I miss my future husband` 的评论区判成"没价值"，而实际上它告诉你的是：
这条广告卖的是**向往感**，观众也确实是这么接收的 —— 这是内容/投放层面的结论。

**先看到什么就聚什么，聚完再判断每一簇能拿来干嘛。**

⚠️ **也不要把它当商品评论读。** 这里的人 99% 没买过 —— 他们的负面是**怀疑**
（`is it actually waterproof?`），不是**失望**（`it leaked on day 2`）。
两者长得像，但一个是详情页要回答的，一个是产品要改的。区别见 §4。

## 工具

| 工具 | 干什么 | 花几次额度 |
|---|---|---|
| `cl_tk_video_info` | 视频详情 + 平台 AI 关键词 | 1-2 |
| `cl_tk_comments` | 抓评论、去噪、排成紧凑文本 | 每页 1 |
| `cl_save` | 结果落到本机 | 0 |

没有脚本，没有路径，不用 `cd`。额度不足时工具会直接告诉你还剩几次。

## 1. 拿到 video id

用户可能给链接。id 就是 URL 里 `/video/` 后面那串 19 位数字：

```
https://www.tiktok.com/@user/video/7392317557593640234
                                   └────────┬────────┘
```

短链（`vm.tiktok.com/xxx`）要先展开：`curl -sIL <短链> | grep -i ^location`。

## 2. 先拉视频详情 —— 别跳过

**评论只有放回视频语境里才读得懂。** 一条 `sudden wave might ruin everything` 的评论，
不看视频你不知道那是在说海边约会的场景风险，还是在说产品防水。

```
cl_tk_video_info { aweme_id: "7655717917069282582" }
```

重点看：

- **`广告: 是`** —— 广告的评论区通常在评「氛围」不在评产品
- **文案里的卖点** —— 作者主动强调什么，对照评论区看观众有没有接住
- **评论率** —— 292 万播放只有 709 评论，说明是"看完就划走"的氛围内容
- **hashtag** —— `#datenight #couple` 和 `#review #vs` 是两种完全不同的评论区
- **平台标AI** —— 评论区出现 `C'est IA` / `this is fake` 时，用这个直接证伪或证实

### AI 词：平台自己认为这条视频在讲什么

输出末尾的 `AI标题 / AI摘要 / AI词` 来自平台为 SEO 生成的文章。
**覆盖率约 4/10**，拿不到是常态，工具会静默降级成「无」。

它的价值不在"帮你看懂视频"（文案已经够了），而在于它是**第三方视角**：

- **AI 词全是场景词、没有产品参数词** → 平台也认为这是氛围内容。
  实测某条投影仪广告的 AI 词是 `outdoor movie night ideas`、`date night ideas for couples`
  —— 讲的是**约会场景**不是投影仪。这和评论区的表现互相独立地印证同一件事
- **AI 词里有参数/对比词**（`1080P vs 4K`、`best budget projector`）→ 讨论向视频，值得挖深
- **这些词是现成的长尾词**，比视频文案（一堆 emoji 和标签）更适合当后续研究的输入

## 3. 先体检，再翻够页

```
cl_tk_comments { aweme_ids: ["7392317557593640234"], pages: 1 }
```

多条视频合并分析就并列传：`aweme_ids: ["7392...", "7393...", "7394..."]`

**先跑 1 页体检**，看输出头部的「高购买意图」占比 —— 这是「评论区是不是在认真讨论」
的指标。<10% 说明是娱乐向评论区（全是段子），换视频。

体检过了就**翻够页**：

| 1 页体检结果 | 翻几页 |
|---|---|
| 高购买意图 <10% | 别翻了，换视频 |
| 10~30% | 6 页 |
| ≥30% | 8 页 |

**一页顶多 50 条，3 页只有 150 条 —— 拆二级话题根本不够分。**
一个 60% 是「被打动」的评论区，3 页里那组也就 90 条，切成 3 栏每栏 30 条，
你能引用的还是那 5 条最热的；翻到 8 页有 300+ 条，长尾里才会露出
「给妈买」「露营用」这种切得开的二级话题。**多翻 5 页比漏掉一个人群便宜得多。**

⚠️ **翻页有衰减**：第 3 页起平台开始给重复的（已按 `cid` 去重），实测 49/49/30/38 递减。
8 页拿到 250~320 条是正常的，**不是抓失败**。

⚠️ **体检那一页不会重复计费** —— 服务端缓存 10 分钟，所以 `pages=8` 时第一页是白送的。
放心先体检。

`limit` 参数只打前 N 条（按点赞降序），评论多到烧上下文时用。

### 输出怎么读

```
# video 7649322678351908127  抓49/平台7186  留41  高购买意图33%
# 共 41 条待读  总赞 3,211  语言 en:35 es:4 id:2
# 其中 16 条(39%) 带「讲自己处境/决策」的语言(标 !)
# 格式: [序号] ♥点赞 r回复 | 正文   (按点赞降序，不按主题排)

[1]!💰♥234 r12 en | mine leaked on day 2
```

**排序是按点赞降序，不是按信号分。** 这是刻意的 —— 点赞 =「多少人有同感」，
是唯一不预设「评论区该聊什么」的排序。一旦按痛点语言排，羡慕/玩梗/质疑这些簇
会整体沉底，读的人就会误以为评论区没东西。

`!` 标记（第一人称经历 / 抱怨故障 / 求推荐 / 疑问句 / 对比替代 / 价格 / 具体数字，
都**不绑品类**）只是标记，不参与排序也不决定去留。它给你一个视频级的密度指标，
不是帮你挑评论。

`💰` 是平台自己的分类器。⚠️ **不要拿它单条挑评论** —— 实测反推它更像
「这条是不是在认真提问」的分类器，`Why unwashed?` 这种也会被标 True。
**聚合看可信，单条看不可信。**

## 4. 你手上是哪种评论 —— 先认清这件事

**视频评论区的人 99% 没买过。** 这一句决定了后面所有的解读方式。

| | 视频评论（本 skill） | 商品评论 |
|---|---|---|
| **谁在说** | 被算法喂到的路人，多数没听过这品类 | 已付钱的人 |
| **什么时候说** | 买之前，甚至"还不知道自己想买"之前 | 收到货之后 |
| **说给谁听** | **说给评论区听** —— 玩梗、抢热评、抬杠、认亲 | 说给下一个买家和卖家听 |
| **负面长什么样** | **怀疑**：`is it actually waterproof?` | **失望**：`it leaked on day 2` |
| **能不能定量** | ❌ 平台热度混排，样本有偏 | ✅ 星级分布一次拿到 |
| **一句话** | **"我为什么还没买"** | **"我买了之后后悔什么"** |

两个直接影响判读的推论：

- **别在视频评论区做定量陈述。** 结论里不能写"用户普遍认为 X" —— 你看到的是平台挑的
  热评，不是随机样本。要写只能写"热评里有一簇在说 X，占抓到的 N 条的约 M%"。
- **爆款视频评论区的负面天然稀薄** —— 不感兴趣的人直接划走，不留言。
  所以这里出现的「将就方案」簇价值极高：那是**在一条卖爆的片子底下仍然没被说服的人**，
  浓度远高于随机人群。

## 5. 聚类：评论区在讨论什么

**先聚，别先筛。** 按「用户在说同一件事」归簇，不是按词形 ——
`"I just use a pot"` 和 `"my instantpot takes 20 min"` 是同一簇（质疑这品类的必要性），
虽然一个字都不重合。

常见的簇型（不是清单，实际有什么聚什么）。**「侧」这一列是关键**：
需求侧的簇你现在就能下结论，交付侧的簇你手上的数据不够，只是线索：

| 簇型 | 长什么样 | 侧 | 拿到之后干什么 |
|---|---|---|---|
| **将就/替代方案** | "I just use a pot"、DIY 做法 | 需求 | **最高价值**。这群人在爆款底下都没被说服 → 把这句话当选品命题深挖 |
| **购买卡点** | "$220 difference, is it worth it?" | 需求 | 逐条抄成详情页 FAQ / 五点，这是买家原话 |
| **求推荐/要链接** | "where can I buy this??" | 需求 | 供给缺口。广告没留链接 = 投放问题 |
| **向往/代入** | "I miss my future husband"、"My dream" | 需求 | 内容侧：这条片子卖的是意境不是参数。抄它的镜头和文案结构，别抄卖点 |
| **场景吐槽** | 沙子、蚊子、涨潮 | 需求 | 场景摩擦，可能是配件机会。是**场景**的摩擦不是**产品**的缺陷 |
| **质疑真假** | "this is fake"、"C'est IA" | 需求 | 信任问题。先用「平台标AI」证伪/证实 |
| **别家的失败经历** | "my last one died in 6 months" | **交付** | ⚠️ 说的多半是别的品牌。是**竞品情报和文案素材**，不是你的改进点 |
| **对本品的抱怨** | 直接吐槽片中这个产品 | **交付** | 样本极少且不可定量。**只当线索**，要去商品差评验证 |
| **玩梗/跑题** | 接龙、认亲、和产品无关 | — | **只计数，不出页**。占比是信号，原话没用 |

**占比比内容更重要。** 一个 40% 是「向往/代入」的评论区，和一个 40% 是「将就方案」的
评论区，是两种完全不同的东西 —— 前者说明内容做对了但产品没被记住，后者说明品类有机会。

簇控制在 4-8 个。太碎说明你在按词形分，把语义相同的合掉。

## 6. 判断这个评论区能拿来干嘛

聚完再判断，**不要反过来**。四种结论都是合法的：

- **选品有料** —— 有「将就方案」「购买卡点」簇。最理想，直接下结论
- **有线索但要换数据源** —— 交付侧的簇冒头了，但视频评论区给不了普遍性。
  **别硬下结论**，明确写出「该去查哪个品的商品差评」。这一档最容易被误判成
  "选品有料"然后写出没有证据的结论
- **选品没料但内容有料** —— 全是向往/玩梗。说明这条片子的内容策略值得抄，
  但挖不出产品需求。**这不叫"没价值"**，是价值在别处
- **确实没料** —— 纯玩梗跑题。直说，并给出该换什么片子

判断评论区类型的**先验信号**（读评论前就能看出来）：

- 输出头部的 **`!` 占比**：<20% 基本是氛围向，>40% 是讨论向
- **语言分布**：单一语种多半在认真讨论；多语种混杂说明是靠画面传播的氛围内容
- **高购买意图占比**：<10% 娱乐向，≥20% 值得翻深
- **评论率**：292 万播放才 709 评论 = 看完就划走

## 7. 保存

```
cl_save {
  kind: "cl-tk-comments",
  id: "7392317557593640234",
  data: { video: {...}, audience: {...}, groups: [...] }
}
```

面板 4 秒内会出现这条记录。

### 四个固定分组

别自创分组名。没有的组直接省略。

| 组 | 收什么 | 卖家拿来干嘛 | 挖多深 |
|---|---|---|---|
| **他们被什么打动** | 心动、代入、想买给谁 | 这些句子可直接当文案 | **挖到底**，3-4 个 topic |
| **他们在嫌什么** | 抱怨、劝退、顾虑 | 文案要处理的异议 | **挖到底**，2-4 个 |
| **他们在问什么** | 在哪买、多少钱、怎么用 | 详情页 FAQ 照着写 | 2-3 个够了 |
| **他们提到了谁** | 评论区自己搬出来的别的牌子 | 竞品清单 | 有就写，常常没有 |

⚠️ **玩梗/跑题/互关不单独成组。** 它们只在 `audience.topics` 里占一条（`cls: "noise"`）。
理由：占比是信号，原话不是。识别出来计数，然后丢掉。

**顺序按价值排**：打动 / 嫌 在前，问 在后。`groups[]` 的顺序就是面板上的顺序。

### 二级话题：打动/嫌 这两组要拆细

这两组是价值所在，**别用一个大 topic 兜住**。「99 条被打动」当成一个 topic 是浪费 ——
得问「**他们各自被什么不同的东西打动**」。

切法（按哪个切得开用哪个，不要硬凑）：

- **按谁用** —— 给自己 / 给妈 / 给孩子。`my son always leaves snacks half finished`
  和 `My mom would love this` 是两个人群
- **按什么场景** —— 冰箱上 / 早餐 / 露营 / 收纳。场景词最容易切开
- **按打动他的是什么** —— 外观、原理巧妙、解决了某件烦心事、价格看起来便宜
- **按嫌的是什么层面** —— 用不上（需求不成立）/ 不信（信任）/ 买过说坏（交付）/ 嫌贵（价格）。
  ⚠️ 这四种是**完全不同的异议**，混成一个 topic 就没法用了

**一个 topic 低于 3 条就并掉**，但并之前先想清楚是不是切错了维度。
拆不动就是拆不动 —— 评论区真的只有一种打动方式时，别硬编出第二个。

⚠️ **「他们在嫌什么」哪怕只有几条也要单独成组并拆细。**
爆款视频的负面天然稀薄（§4），4 条负面里混着「需求不成立」和「买过的人说坏」，
这是两件事，价值完全不同 —— 合成一个就把唯一的交付侧线索埋了。

### 每条原话都要中文

**`zh` 是必填**，英文原话也要给中文意思。读的人不一定看得懂英文，
而这些原话正是卖家要抄进详情页的东西 —— 看不懂就用不上。

`text` **必须逐字照抄**，这是唯一能验证你没编的东西。

### data 结构

```jsonc
{
  "video": {
    "id": "7392317557593640234",
    "name": "冰淇淋机评论区",        // 面板上的标题
    "author": "@username",
    "url": "https://www.tiktok.com/@user/video/7392...",
    "play": 4604018, "digg": 291000, "comment": 5598
  },
  "audience": {
    "stats": [ { "label": "头部评论", "value": "142 条" } ],   // 3-4 个大数字
    "bars":  [ { "label": "en", "n": 35 } ],                  // 语言分布
    "topics": [                                               // 和 groups 一一对应
      { "label": "成功种草", "n": 62, "cls": "love" },
      { "label": "购买咨询", "n": 24, "cls": "ask" },
      { "label": "顾虑与劝退", "n": 18, "cls": "gripe" },
      { "label": "竞品提及", "n": 6, "cls": "rival" },
      { "label": "纯娱乐互动", "n": 32, "cls": "noise" }       // 只在这里出现
    ],
    "reads": [ "这 142 条是平台按热度排在最前面的，不是随机样本" ]
  },
  "groups": [
    {
      "title": "他们被什么打动",      // 必填
      "hint": "可直接当文案的句子",
      "count": 62,
      "topics": [
        {
          "name": "给妈妈买",          // 必填，用大白话
          "count": 22,
          "likes": 1203,
          "quotes": [
            { "text": "getting this for my mom",   // 逐字
              "zh": "给我妈买一个",                  // 必填
              "likes": 340,
              "tag": "" }                           // 可选，比如标牌子
          ]
        }
      ]
    }
  ],
  "data_note": "抓了 8 页共 312 条，去噪后 261 条"
}
```

只有 `video.name`、`groups[].title`、`groups[].topics[].name` 是必填的，
其余字段按情况写 —— 校验是宽松的，不会因为少一个可选字段被打回。

⚠️ **画像页的 `topics[].label` 用「意图词」，不用组标题那种口语。**
「他们在问什么」是描述行为；画像要的是一眼识别意图 → 「购买咨询」。
用「顾虑与劝退」而不是「表达痛点」：这组多数人**没买过**，说的是买之前的顾虑，
叫「痛点」会把人往商品差评的方向误导。

⚠️ **`stats[]` 只放和评论区本身有关的数字** —— 条数、总赞、语种数。
播放量、评论率这类**视频级**指标不要放，掺进去会让人以为在做内容表现分析。

⚠️ **措辞：说「头部评论 N 条」，不要说「抓了 N 条」。**
「抓取」是实现细节，读的人不关心，而且听起来像样本残缺。

## 8. 什么时候不保存

用户只是随口问「这条评论区在说什么」、或明说不要保存时，直接在对话里给结论。

多条视频横向对比时，各存各的，然后在对话里给一张对比表。

## 坑

- **单条视频的评论抓不全**。平台给的是热度混合排序，没有任何排序/筛选参数
  （试过全被静默忽略）。所以你看到的是「平台认为热的那一撮」—— 结论里别写"用户普遍认为"
- **结果不稳定**：同参数连打几次会有 1-2 条进出。别把单条评论的有无当结论
- **翻页第 3 页起有重叠**，已按 `cid` 去重，实测 49/49/30/38 递减
- 评论区可能是多语种（实测混 ja/ko/id）。非英文的照样读，痛点不分语言
