# TK 评论区聚类

输入一个视频 id，输出**这条视频的评论区到底在讨论什么**，按语义聚成簇，
再说每簇有什么用。

⚠️ **不要预设评论区在聊痛点。** 评论区可能在羡慕、玩梗、质疑真假、认亲、
纯跑题 —— 这些都是真实信号，只是指向不同用途。带着"找痛点"的框去读，
会把一个 40% 的人在喊 `I miss my future husband` 的评论区判成"没价值"，
而实际上它告诉你的是：这条广告卖的是**向往感**，观众也确实是这么接收的
—— 这是内容/投放层面的结论。

**先看到什么就聚什么，聚完再判断每一簇能拿来干嘛。**

⚠️ **也不要把它当商品评论读。** 这里的人 99% 没买过 —— 他们的负面是**怀疑**
（`is it actually waterproof?`），不是**失望**（`it leaked on day 2`）。
两者长得像，但一个是详情页要回答的，一个是产品要改的。区别见 §3。

## 1. 拿到 video id

用户可能给链接。id 就是 URL 里 `/video/` 后面那串 19 位数字：

```
https://www.tiktok.com/@user/video/7392317557593640234
                                   └────────┬────────┘
```

短链（`vm.tiktok.com/xxx`）要先展开：`curl -sIL <短链> | grep -i ^location`。

**如果用户是从面板上某条视频点进来的**，指令里会带两个参数：
`<aweme_id> <from_run>`。第二个是那次搜索的 run_id，落盘时填进 `from_run`，
面板才能把这份分析挂回那条视频下面（见 §6）。

## 2. 先拉视频详情 —— 别跳过

**评论只有放回视频语境里才读得懂。** 一条 `sudden wave might ruin everything`
的评论，不看视频你不知道那是在说海边约会的场景风险，还是在说产品防水。

```
cl_tk_video { aweme_id: "7655717917069282582" }
```

重点看：

- **`💰 广告/恰饭内容`** —— 广告的评论区通常在评「氛围」不在评产品
- **文案里的卖点** —— 作者主动强调什么，对照评论区看观众有没有接住
- **播放/评论比** —— 292 万播放只有 709 评论，说明是"看完就划走"的氛围内容
- **标签** —— `#datenight #couple` 和 `#review #vs` 是两种完全不同的评论区
- **`🤖 平台标记 AI 生成`** —— 评论区出现 `C'est IA` / `this is fake` 时，
  用这个直接证伪或证实

### AI 文章：平台自己认为这条视频在讲什么

输出末尾的 `AI标题 / AI摘要 / AI词` 来自 TikTok 为 SEO 生成的文章。
**覆盖率约 4/10**，拿不到是常态（工具会明说"没有 AI 文章"，那不是调用失败）。

它的价值不在"帮你看懂视频"，而在于它是**第三方视角**：

- **AI 词全是场景词、没有产品参数词** → 平台也认为这是氛围内容
- **AI 词里有参数/对比词**（`1080P vs 4K`、`best budget projector`）→
  讨论向视频，值得挖深
- **这些词是现成的长尾词**，比视频文案更适合当后续选品研究的输入

## 3. 抓取：先体检再决定翻几页

```
cl_tk_comments { aweme_ids: ["7392317557593640234"], pages: 1 }
```

**先跑 1 页体检。** 输出头部会报「高购买意图 N/M = X%」，那是
「评论区是不是在认真讨论」的指标：

| 1 页体检结果 | 翻几页 |
|---|---|
| 高购买意图 <10% | 别翻了，见下面 |
| 10~30% | 6 页 |
| ≥30% | 8 页 |

⚠️ **0% 是真实结果，不是工具坏了，不要重试。** 实测一条 656 万播放的
ADHD 吊椅视频整整 50 条评论一个都没命中 —— 那是爆火的氛围内容，
没人在谈购买。这本身就是结论（§5 的「选品没料但内容有料」）。

⚠️ **<10% 时仍然可以继续读那 50 条**，只是别再花钱翻页。判断要基于内容，
不是基于这一个数。

**一页顶多 50 条，3 页只有 150 条 —— 拆二级话题根本不够分。**
翻到 8 页有 300+ 条，长尾里才会露出「给妈买」「露营用」这种切得开的二级话题。

⚠️ 翻页有衰减：第 3 页起平台开始给重复的（服务端已按 cid 去重），
实测 49/49/30/38 递减。8 页拿到 250~320 条是正常的，不是抓失败。

**排序是平台的热度混排，不是按赞降序，也没有任何排序参数**（传了被静默忽略）。
这一条决定了结论里不能写「用户普遍认为」。

## 4. 你手上是哪种评论 —— 先认清这件事

**视频评论区的人 99% 没买过。** 这一句决定了后面所有的解读方式。

| | 视频评论（本 skill） | 商品评论 |
|---|---|---|
| **谁在说** | 被算法喂到的路人，多数没听过这品类 | 已付钱的人，含一批返现水评 |
| **什么时候说** | 买之前，甚至"还不知道自己想买"之前 | 收到货之后 |
| **说给谁听** | **说给评论区听** —— 玩梗、抢热评、抬杠、认亲 | 说给下一个买家和卖家听 |
| **负面长什么样** | **怀疑**：`is it actually waterproof?` | **失望**：`it leaked on day 2` |
| **能不能定量** | ❌ 平台热度混排，样本有偏 | ✅ 分页扎实 |
| **有点赞吗** | 有，能判普遍性 | 没有 |
| **一句话** | **"我为什么还没买"** | **"我买了之后后悔什么"** |

两个直接影响判读的推论：

- **别在视频评论区做定量陈述。** 结论里不能写"用户普遍认为 X" ——
  你看到的是平台挑的热评。只能写"热评里有一簇在说 X，占抓到的 N 条的约 M%"。
- **爆款视频评论区的负面天然稀薄** —— 不感兴趣的人直接划走，不留言。
  所以这里出现的「将就方案」簇价值极高：那是**在一条卖爆的片子底下仍然
  没被说服的人**。

## 5. 聚类：评论区在讨论什么

**先聚，别先筛。** 按「用户在说同一件事」归簇，不是按词形 ——
`"I just use a pot"` 和 `"my instantpot takes 20 min"` 是同一簇
（质疑这品类的必要性），虽然一个字都不重合。

常见的簇型（不是清单，实际有什么聚什么）。**「侧」这一列是关键**：

| 簇型 | 长什么样 | 侧 | 拿到之后干什么 |
|---|---|---|---|
| **将就/替代方案** | "I just use a pot"、DIY 做法 | 需求 | **最高价值**。这群人在爆款底下都没被说服 |
| **购买卡点** | "$220 difference, is it worth it?" | 需求 | 逐条抄成详情页的 FAQ / 五点 |
| **求推荐/要链接** | "where can I buy this??" | 需求 | 供给缺口。广告没留链接 = 投放问题 |
| **向往/代入** | "I miss my future husband"、"My dream" | 需求 | 内容侧：这片子卖的是意境不是参数 |
| **场景吐槽** | 沙子、蚊子、涨潮 | 需求 | 场景摩擦，可能是配件机会 |
| **质疑真假** | "this is fake"、"C'est IA" | 需求 | 信任问题。先用平台的 AI 标记证伪/证实 |
| **别家的失败经历** | "my last one died in 6 months" | **交付** | ⚠️ 说的多半是别的品牌。是竞品情报，不是你的改进点 |
| **对本品的抱怨** | 直接吐槽片中这个产品 | **交付** | 样本极少。**只当线索**，要去查商品差评验证 |
| **玩梗/跑题** | 接龙、认亲、和产品无关 | — | **只计数，不出组**。占比是信号，原话没用 |

**占比比内容更重要。** 一个 40% 是「向往/代入」的评论区，和一个 40% 是
「将就方案」的评论区，是两种完全不同的东西。

簇控制在 4-8 个。太碎说明你在按词形分，把语义相同的合掉。

## 6. 判断这个评论区能拿来干嘛

聚完再判断，**不要反过来**。四种结论都是合法的：

- **选品有料** —— 有「将就方案」「购买卡点」簇。最理想，直接下结论
- **有线索但要换数据源** —— 交付侧的簇冒头了，但视频评论区给不了普遍性。
  **别硬下结论**，明确写出「该去查哪个品的商品差评」
- **选品没料但内容有料** —— 全是向往/玩梗。这条片子的内容策略值得抄。
  **这不叫"没价值"**，是价值在别处
- **确实没料** —— 纯玩梗跑题，且和品类无关。直说，并给出该换什么片子

判断评论区类型的**先验信号**（在读评论前就能看出来）：

- **高购买意图占比**：<10% 娱乐向，10~30% 值得翻深，≥30% 讨论很密
- **语言分布**：单一语种多半在认真讨论；多语种混杂说明是靠画面传播的氛围内容
- **播放/评论比**：292 万播放才 709 评论 = 看完就划走

⚠️ **不要拿 💰 标记单条挑评论。** 它更像「这条是不是在认真提问」的分类器。
**聚合看可信，单条看不可信。**

## 7. 落盘

用 `cl_save`：

```
cl_save {
  kind: "cl-tk-comments",
  slug: "ziploc-sealer",
  from_run: "tksearch_20260917_a3f2",   // 从面板某条视频点进来时必填
  data: { video, analyzed_at, audience, groups, data_note }
}
```

⚠️ **面板产出是「整理」，不是「判断」。**
「他们在问在哪买」是观察，「所以你该挂链接」是推论 —— **后者不写进 JSON**。
§4~§6 那些判断仍然要做，但**在对话里说**，两三句话。

结构：

```json
{
  "video": {
    "id": "7628036818079976735",
    "url": "https://www.tiktok.com/@dreambunny22/video/7628036818079976735",
    "author": "@dreambunny22",
    "name": "封口机评论区"
  },
  "analyzed_at": "2026-09-17",
  "audience": {
    "stats": [
      {"n": "240", "label": "头部评论", "sub": "平台共 891 条 · 8 页"},
      {"n": "2,175", "label": "这些评论的总赞", "sub": "最热 1 条独占 1,568"},
      {"n": "9", "label": "语种", "sub": "en 183 · es 36 · pt 8"}
    ],
    "bars_title": "他们说的什么语言",
    "bars": [{"label": "英语", "n": 183, "pct": 76}],
    "topics_title": "他们走到哪一步了",
    "topics_hole": ["240", "条"],
    "topics": [
      {"label": "只说想要，没说为什么", "n": 149, "pct": 62, "cls": "love"},
      {"label": "直接要买：求链接/问价", "n": 42, "pct": 18, "cls": "ask"},
      {"label": "多少钱", "n": 20, "pct": 8, "cls": "ask", "sub": true}
    ],
    "reads": ["这 240 条是平台按热度排在最前面的，不是随机样本，也不是全部 891 条。"]
  },
  "groups": [
    {
      "title": "他们被什么打动",
      "hint": "171 条心动。占了这批评论的七成",
      "count": 171,
      "topics": [
        {
          "name": "他们想到了具体的谁、具体的地方",
          "count": 9, "likes": 1583,
          "quotes": [
            {"text": "yo necesito uno justo así en la refri",
             "zh": "我冰箱上就需要一个这样的",
             "likes": 1568}
          ]
        }
      ]
    }
  ],
  "data_note": {"caveats": ["平台给的是热度混排，不是随机样本，也没有排序参数"]}

```

- **`video.id` 必填** —— 面板靠它把这份分析挂回搜索结果里的那条视频。
  少了它这条视频会永远显示「未分析」。
- `cls` 只能填 `ask` / `gripe` / `rival` / `love` / `noise` / `none`。面板按它上色。

### 画像（`audience`）：按「他们走到哪一步了」切，不按说话的形式切

⚠️ **别把「成功种草」和「购买咨询」并排当两个桶** —— 它们不互斥。
`I need this` 和 `Where can I buy it` 是同一件事的两半，同一个人两句都想说。

按**离下单还有多远**切，这个轴才是互斥的：

| 分档 | 收什么 | 怎么认 |
|---|---|---|
| **只说想要，没说为什么** | `I need`、`Genius!!!` | 20 字以内、没有任何具体信息的纯感叹 |
| **被种草** | 说出了场景、人群、新用法 | 有具体名词：冰箱、我儿子、出差 |
| **直接要买** | 求链接、问在哪买、问价 | 开口要购买信息 |
| **顾虑与劝退** | 用不上、不信、买过说坏 | —— |
| **纯娱乐互动** | 玩梗、互关、鸡汤 | 只计数 |

**「只说想要，没说为什么」这一档往往占一半以上，别嫌它难看，如实写。**
62% 的人只会说 `I need` —— 这本身就是结论。硬把它拆成几栏是凑数。

**「被种草」这一档才是要挖深的**，它是唯一能长出二级话题的。

二级档在 `topics[]` 里紧跟父档，加 `"sub": true`：**不进环，只进图例**
（缩进显示），百分比按占总数算。所以父档的 n 要**包含**它的子档。
图例会自动加 `└` 前缀，**`label` 里别再写「其中」**。
各档加起来不等于总数时，补一条 `{"label":"未归类","cls":"none"}`。

⚠️ **画像用「意图词」，不用内页那种口语标题**：

| 组标题（口语，给人读原话） | `topics[].label`（意图词） |
|---|---|
| 他们在问什么 | **购买咨询** |
| 他们在嫌什么 | **顾虑与劝退** |
| 他们提到了谁 | **竞品提及** |
| 他们被什么打动 | **成功种草** |
| （不做组，只进画像） | **纯娱乐互动** |

用「顾虑与劝退」而不是「表达痛点」：这组多数人**没买过**，
说的是买之前的顾虑，不是已购用户的使用问题（§4）。

⚠️ **`stats[]` 只放和评论区本身有关的数字** —— 条数、总赞、语种数、点赞集中度。
播放量、评论率这类**视频级**指标不要放。

⚠️ **措辞：说「头部评论 N 条」，不要说「抓了 N 条」。**
样本口径放进 `reads[]` 和 `data_note.caveats` 交代。

### 四个固定分组（`groups`）

别自创分组名。没有的组直接省略。

| 组 | 收什么 | 卖家拿来干嘛 | 挖多深 |
|---|---|---|---|
| **他们被什么打动** | 心动、代入、想买给谁 | 这些句子可直接当文案 | **挖到底**，3-4 个 topic |
| **他们在嫌什么** | 抱怨、劝退、顾虑 | 文案要处理的异议 | **挖到底**，2-4 个 |
| **他们在问什么** | 在哪买、多少钱、怎么用 | 详情页 FAQ 照着写 | 2-3 个够了 |
| **他们提到了谁** | 评论区搬出来的别的牌子 | 竞品清单 | 有就写，常常没有 |

⚠️ **玩梗/跑题/互关/鸡汤不做组。** 只在画像的 `topics[]` 里占一条
（`cls: noise`）。占比是信号，原话不是。

**`groups[]` 数组的顺序就是面板上的顺序，按价值排**：打动 / 嫌 在前，问 在后。

**每个 topic 3-5 条原话。** 低于 3 条就并掉，但并之前先想清楚是不是切错了维度。

### 二级话题：打动/嫌 这两组要拆细

这两组是价值所在，**别用一个大 topic 兜住**。
「99 条被打动」当成一个 topic 是浪费 —— 得问「**他们各自被什么不同的东西打动**」。

拆的切法（按哪个切得开用哪个，不要硬凑）：

- **按谁用** —— 给自己 / 给妈 / 给孩子 / 给室友
- **按什么场景** —— 冰箱上 / 早餐 / 露营 / 收纳。场景词最容易切开
- **按打动他的是什么** —— 外观、原理巧妙、解决了具体某件烦心事、价格看起来便宜
- **按嫌的是什么层面** —— 用不上（需求不成立）/ 不信（信任）/ 买过说坏（交付）/
  嫌贵（价格）。⚠️ 这四种是**完全不同的异议**，混成一个 topic 就没法用了

⚠️ **「他们在嫌什么」哪怕只有几条也要单独成组并拆 topic。**
爆款视频的负面天然稀薄（§4），4 条负面里混着「需求不成立」和「买过的人说坏」，
合成一栏就把唯一的交付侧线索埋了。

拆不动就是拆不动 —— 评论区真的只有一种打动方式时，别硬编出第二个 topic。

### 每条原话都要中文

**`zh` 是必填，英文原话也要给中文意思。** 读面板的人不一定看得懂英文，
而这些原话正是卖家要抄进详情页的东西 —— 看不懂就用不上。

`text` 必须逐字照抄，这是唯一能验证你没编的东西。

### 重跑同一条视频

**用同一个 slug 再存一次即可** —— 每次运行都是新的一条记录，不会覆盖上一次。
面板按时间显示最新那份，历史仍然打得开（这类研究本来就有时间维度，
一条视频的评论区半年后是会变的）。

## 8. 收尾

写完后在对话里说：

- 这条视频是什么、是广告还是自来水
- 抓了几页、头部评论多少条、高购买意图占比多少
- **§6 的判断**：这个评论区能拿来干嘛（选品有料 / 要换数据源 / 内容有料 / 没料），
  两三句话，给出下一步该跑什么
- 提示：结果已经在面板的 TikTok 那一格

**不要把所有簇和原话列在对话里** —— 面板是给这个用的。
对话里只给面板上没有的东西：判断和下一步。

## 坑

- **单条视频的评论抓不全**。平台给的是热度混合排序，**不是按赞降序**，
  也没有任何排序/筛选参数。结论里别写"用户普遍认为"。
- **结果不稳定**：同参数连打几次会有 1-2 条进出。别把单条评论的有无当结论。
- **评论区可能是多语种**（实测混 es/id/de）。非英文的照样读，痛点不分语言。
- **老视频的评论仍在增长**：2023 年发的视频，2026 年还有新评论。
  评论的时间跨度大是正常的。
